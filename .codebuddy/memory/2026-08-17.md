## 抽奖系统 - 修复"抽中结果与弹窗不符"bug
- 现象：抽中"感谢参与"却弹"话费券"，弹窗结果与轮盘停靠/判定结果错位。
- 根因：`js/app.js` 的 `doDraw` 已通过 `rollIndex` 确定中奖槽位 `idx` 并 `spinTo(idx)` 转盘，但 `resolveDraw()` 却丢弃 `idx`，改用 `hitSector()` 反推指针扇区（脆弱、多余）。
- 修复：`resolveDraw(idx)` 改为接收 `idx` 参数（闭包传参），直接使用判定结果，删除 `hitSector()` 反推调用。保证弹窗 = 加权判定 = 轮盘停靠三者严格一致。
- 验证：`node --check js/app.js` 通过；曾用 node 模拟 10 万次确认角度数学本身自洽（hitSector 与 spinTo 恒等），错位源于"反推"这一层架构，非角度公式。
- 经验：`demo-core.js` 参考实现用 `onResult(idx)` 直接回传 idx，而非反推，是正确做法。

## 抽奖系统 - 二次修复"抽中内容与提示不符"（真因）
- 第一次修复（resolveDraw 直接传 idx）只能保证"弹窗=判定结果"，但用户仍反馈不符。
- 真因：`draw()` 绘制奖品图/文字时用了 `ctx.rotate(mid - Math.PI/2)`（第128/135行），比扇区中心 `mid` 多转了 **-90°（2个扇区）**。而 `spinTo(idx)` 是对齐"扇区数学中心"到指针。两者不对称 → 指针下显示的扇区内容 vs 数学扇区 idx 偏移 2 个扇区 → "抽中A看到B"。
- 该固定偏移与 canvas 旋转方向无关（draw 比 spinTo 永远多转 -π/2，确定性 bug）。`demo-core.js` 也有同样的 -π/2 写法。
- 修复：去掉 draw 里多余的 `- Math.PI/2`；图片改为 `rotate(mid)...translate...rotate(-mid)` 使其正立，文字改为 `rotate(mid)` 沿半径放射，均归位扇区中心，与 spinTo 对齐。
- 验证：`node --check` 通过；node 模拟 10万次确认角度数学自洽（错位源于绘制偏移而非角度公式）。
